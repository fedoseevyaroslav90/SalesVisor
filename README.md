# SalesVisor — контроль исполнения заказов покупателей

Веб-приложение для менеджеров и отдела сервиса. Оно собирает в одном окне:

- **Светофор** (Metabase, вопрос 573): первая требуемая дата клиента («Первая декада»), где заказ сейчас («Текущая декада»), смещение и цвет;
- **Отчёт по отрезкам** (Metabase, вопрос 522): требуемая дата, план отгрузки и этап каждого отрезка (произведён, на складе, готов, в пути, отгружен, отфактурирован), менеджер, номер задачи в Битрикс24.

При каждой загрузке приложение сравнивает свежие данные с прошлыми и записывает в журнал все переносы декад и треб. дат, смену цвета и этапа. Лента «Изменения» показывает, что сдвинулось за день, неделю или месяц.

Описание проекта и связки с Битрикс24: [docs/proekt-v2.md](docs/proekt-v2.md). Первый прототип на Node.js лежит в `prototype-v1/` для истории.

## Экраны

- **Заказы / Позиции.** Переключатель: строка — заказ (итог по его позициям) или позиция (изделие, линия, этап, сроки). Менеджер, отдел, поиск (заказ, клиент, менеджер, изделие), «в работе», «хвосты» (срок прошёл больше полугода назад) или «все». Панель **«Отбор»**: клиент, линия, группа этапа, срок сейчас и первая дата клиента (эта/следующая декада, месяц, свой период), смещение от N дней, отметки (просрочено, несоответствия, без Битрикс24, с комментариями, в плане производства). Отбор идёт по позициям: заказ показывается, если подошла хоть одна его позиция, и считается по подошедшим. Плитки заказов: просрочка, цвета, без светофора, без Битрикс24, несоответствия. Сортировка — щелчком по заголовку любой таблицы (по возрастанию → по убыванию → как было). **«Скачать в Excel»** — все строки отбора в том же порядке (`/api/export.xlsx`), **«Ссылка на отбор»** — отбор живёт в адресе страницы (`#…`), последний отбор восстанавливается. Лента позиций отбирается, сортируется и листается на сервере (`/api/positions`).
- **План на день, Диспетчерский, Изменения.** Поиск по строке, сортировка по столбцам и выгрузка таблицы на экране в CSV для Excel.
- **Преднастройки сотрудника** (`/api/prefs`, по алиасу портала): «Мои отборы», последний отбор, «Мои заказы» (свой логин SAP), скрытые столбцы. Выбор нескольких значений в отборе (менеджер, отдел, линия, этап, причина). Кнопка ▸ раскрывает позиции заказа; колонка «МП / опоздание» — сортировка по приоритету МП × дни опоздания к первой дате.
- **Статистика.** OTD позиций и заказов к первой дате клиента, отчёт по срокам по месяцам (в срок / +1…+4 декады / не выполнено), глубина просрочки, топ заказчиков, направления, причины, линии (`/api/stats`).
- **План на день** считает производственные сутки с 08:00 до 08:00. Отметки «Z6 в начавшейся декаде» и «опоздание больше 30 дн.»; лента изменений — новые позиции и смена причины отклонения. Логика и что ещё не сделано — [docs/logika-iz-vygruzki-claude.md](docs/logika-iz-vygruzki-claude.md).
- **Карточка заказа.** Связь с задачей и сделкой Битрикс24: номер из SAP или указанный вручную, при настроенном вебхуке с ответственным и сроком. Позиции со светофором, первой и текущей декадой, треб. датой, планом и этапом. Отрезки открываются по клику. История изменений и комментарии.
- **Изменения.** Все переносы за период, их можно фильтровать по виду.
- **Загрузка.** Ручная загрузка CSV или Excel из Metabase и кнопка «Обновить из Metabase».

## Запуск на сервере

```bash
cp .env.example .env    # заполнить пароль базы, адрес и API-ключ Metabase, вебхук Битрикс24
docker compose up -d    # веб на порту 8102 и синхронизация раз в час
```

Секреты (API-ключ Metabase, адрес вебхука Битрикс24) хранятся только в `.env` на сервере. В репозиторий этот файл не попадает.

В контуре «Инкаб ИИ» приложение стоит на ai-ag за порталом: портал проксирует `/orders/` и подписывает запросы общим секретом `PORTAL_TOKEN` (заголовки `X-SalesVisor-Token`, `X-SalesVisor-User`, `X-SalesVisor-Person`, `X-SalesVisor-Role`). Роль ставит портал по спискам «/manage → Контроль заказов»: `editor` загружает выгрузки и нажимает «Обновить сейчас», `viewer` — всё остальное (за порталом автор комментариев берётся только из заголовков портала). Если Metabase с сервера недоступен, выгрузки кладутся в папку `IMPORT_HOST_DIR` (SFTP завода), синхронизация забирает их раз в час (файлы моложе 2 минут ждут следующего прохода — могут ещё докачиваться). Подробно: раздел 4 в [docs/proekt-v2.md](docs/proekt-v2.md).

### Выкладка в контур (с ноутбука, Git Bash)

```bash
bash deploy/выкладка.sh            # код на ai-ag, копия базы, сборка, пересоздание контейнеров, откат при сбое
bash deploy/портал_окружение.sh    # один раз: общий секрет в окружение портала на ai-gw (без показа)
bash deploy/nginx_загрузка.sh      # один раз: ручная загрузка выгрузок через портал до 160 МБ
```

На сервере: `/opt/salesvisor/{src,.env,pgdata,backups}`, compose-проект `salesvisor` (`docker-compose.yml` + `deploy/docker-compose.ai-ag.yml`), откат — `sudo bash /opt/salesvisor/src/deploy/деплой_ai-ag.sh --rollback`. Карточка размещения — в папке «Внедрение ИИ»: `30_Контур и инфраструктура/33_Разборы и планы/SalesVisor — размещение сервиса «Контроль заказов» (30.09.2026).md`.

## Локальный запуск и тесты

```bash
pip install -r requirements.txt -r requirements-dev.txt
python -m salesvisor load отрезки.csv светофор.csv   # по умолчанию база SQLite в data/
python -m salesvisor serve --port 8000
python -m pytest tests
```
