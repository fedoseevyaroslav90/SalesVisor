# Логика контроля заказов из выгрузки claude.ai (разбор 30.09.2026)

Источник — выгрузка claude.ai владельца от 19.09.2026 (проекты, беседы, память). Слов SalesVisor и номеров
вопросов Metabase 522/573 там нет; логики по контролю заказов много. Главное — беседа «Портативное Python-приложение
для Windows: уточнение требований» (25–30.06.2026, пилот **VOLS-Zakazy**), методика еженедельного отчёта Правлению
(«Отчёт контроля просрочек заказов с позициями», 22–27.06, скилл inkab-board-report), «Анализ сдвижек заказов за
2026 год» (18–22.06), встреча «Светофор мониторинга сдвижек» с отделом сервиса (29.05) и регламент «Причины
отклонения» (вложение беседы 08.09). Ниже — что из этого уже есть в SalesVisor и что предлагается.

## Предлагается дальше (по убыванию пользы)

1. **Мультивыбор в фильтрах** — несколько менеджеров, месяцев, причин (пилот, сообщ. 77).
2. **Группировка «заказ → позиции» со сворачиванием** в самой таблице: в свёрнутой строке № заказа, позиций,
   готово/не готово, МЗ, МП, первая и текущая дата; суммы МП/МЗ/заказа (пилот, сообщ. 58, 62, 117).
3. **МП и приоритет.** Приоритет = МП × дни опоздания; дни = max(текущая треб. дата; сегодня) − дата клиента
   по худшей строке («Критичные заказы…», 10–11.06). Нужна колонка МП из CSV отчёта по отрезкам (сейчас не
   разбирается). Сортировка «что горит» по приоритету.
4. **Настройка столбцов**: видимость, порядок, ширина; доступ ко всем 84 колонкам отчёта по отрезкам (пилот).
5. **Вкладка «Статистика» по текущему отбору**: сводка, по месяцам, глубина просрочки, топ заказчиков по
   просрочке, направления, Z-коды (пилот, сообщ. 71).
6. **Отчёт Правлению** (методика inkab-board-report): месяцы по первой требуемой дате; принято/не принято;
   выполнено в принятую декаду; в заказах и км; среднее число переносов и отклонение в днях; в срок / +1…+4
   декады; топ-10 заказчиков по невыполнению; два OTD — к якорю (~50%) и к принятой декаде (~98%) с подписью.
7. **Якорь — первая по хронологии требуемая дата** из снимков «принято/не принято» (по дате выгрузки SAP, не
   min()): ошибка с min() меняла счёт просрочек с 289 до 499 групп. Нужны снимки приёмки ПДО как ещё один источник.
8. **Производственные сутки 08:00 → 08:00**: выпуск до 08:00 относится к предыдущим суткам — учесть в «Плане на
   день» (сейчас берётся дата окончания как есть).
9. **Контроль регламента Z-кодов**: Z6 после 17:00 крайней даты приёма в декаду; Z1 старше 3 месяцев — список
   нарушений. Z1, Z2, Z3, Z5 и вид заказа есть только в Excel-отчёте ZSD_ORDER_REP — нужен как источник.
10. **«Мои заказы» по логину** (заказов, просрочено, срок ≤ 7, не принято, переносы, OTD) — нужна связь
    сотрудника портала с логином SAP «Создал».
11. **Лента изменений**: события «новый заказ», «смена Z-кода»; окно 15 дней (на дашборде 30).
12. Пороги договоров: 30 дней просрочки — покупатель вправе отказаться (СТП 02-2-01); пени 0,1 %/день до 14 дней
    и 0,5 % с 15-го (договор из беседы 27.08) — подсветка в карточке.

## Подводные камни данных (проверить при доработках)

- «Дата ФактДвиженМтр» — отгрузка, а не выпуск.
- «Создал» в снимках приёмки — автор отчёта, а не инициатор заказа.
- Бывает статус «принят из будущей декады».
- Шнуры считаются в штуках, барабаны в км (каждый барабан — штука).
- Иконка @0A@: в пилоте — «не да», в аналитике ГОЗ — «достигнуто»; сверить с SAP.
- Толкование Z-кодов расходится: в регламенте Z4 — «подписано, аванс получен», в описании SAP — «Готов к
  производству»; Z5 в SAP — «Произведено», в регламенте — только отдел сервиса.
- Светофор в SAP: «Статус» 1.0/0.75 — без сдвига, 0.5 — в пределах декады, 0.25 — соседняя декада, 0.0 — другой
  месяц; решение 10.06 — перевести светофор на поле MatPrice4 (дата клиента, обязательна при Z4).
