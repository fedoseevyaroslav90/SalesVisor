## Не сделано — нужны данные или решение

- **Якорь из снимков «принято/не принято» ПДО** (п. 7) и честный OTD «к принятой декаде» (~98 %): в SalesVisor нет
  файлов приёмки ПДО. Нужны сами файлы (или их выгрузка по SFTP) — тогда якорь будет «первое появление», а не
  первая декада светофора.
- **Z1 старше 3 месяцев, Z2, Z3, Z5, вид заказа** (п. 9): их нет в CSV отчёта по отрезкам — только в Excel-отчёте
  ZSD_ORDER_REP. Нужна его выгрузка как ещё один источник.
- **«Z6 к 17:00 крайней даты приёма»** — точного графика приёма по декадам нет; сейчас проверка «декада срока уже
  началась».
- **Порядок и ширина столбцов** (п. 4) — сделана только видимость.
- **Пени по договору** (п. 12) — договорные, у разных клиентов разные; в интерфейс не выносились.

## Подводные камни данных (проверить при доработках)

- «Дата ФактДвиженМтр» — отгрузка, а не выпуск.
- «Создал» в снимках приёмки — автор отчёта, а не инициатор заказа.
- Бывает статус «принят из будущей декады».
- Шнуры считаются в штуках, барабаны в км (каждый барабан — штука).
- Иконка @0A@: в пилоте — «не да», в аналитике ГОЗ — «достигнуто»; сверить с SAP.
- Толкование Z-кодов расходится: в регламенте Z4 — «подписано, аванс получен», в описании SAP — «Готов к
  производству»; Z5 в SAP — «Произведено», в регламенте — только отдел сервиса.
- Светофор в SAP: «Статус» 1.0/0.75 — без сдвига, 0.5 — в пределах декады, 0.25 — соседняя декада, 0.0 — другой
  месяц; решение 10.06 — перевести светофор на поле MatPrice4 (дата клиента, обязательна при Z4).
